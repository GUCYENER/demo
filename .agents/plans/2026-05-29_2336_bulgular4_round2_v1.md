## Bulgular, kök neden (KANIT), fix

### B4-1 — WHERE kriter ekleyince 400 "kabul etmiyor"
**Kök neden (KANIT):** FE `db_smart_ast_editor.js:548-553` `body.args = spec` gönderiyor,
spec = `{expr, op, value}` (düz). Backend `db_smart_api.py:481` `fn(ast, **body.args)` =
`add_filter(ast, expr=, op=, value=)`. Ama `ast_renderer.add_filter(ast, filt)` tek `filt`
dict param alıyor → **TypeError → 482 → 400 "AST args hatası"**. (Modal `{expr,op,value}`
döndürüyor — `db_smart_filter_modal.js:12`; render `_render_filter` bu şekli bekliyor —
`ast_renderer.py:204-231`; FE optimistic `ast.filters.push(args)` da düz şekli kullanıyor.
Yani sadece backend imzası uyumsuz.)
**Fix:** `ast_renderer.add_filter` düz alanları kabul etsin:
`add_filter(ast, filt=None, *, expr=None, op=None, value=None, column=None)` — filt None ise
kalan alanlardan kur. Geriye uyumlu (hem `{filt}` hem düz). Aynı pattern `add_having` varsa
ona da bak.

### B4-2 — "Çalıştır"da W0SELECT / W0FROM garbage devam
**Kök neden (KANIT):** `_GLUED_KW_RE` anchor'ı `(?<![^\n])` yalnız **satır başı** garbage'ı
yakalıyor. Gerçek SQL'e karşı test ettim: `\n`'den sonra W0FROM temizleniyor ✓, ama
**boşluktan sonra (tek satır / inline) W0FROM TEMİZLENMİYOR** (`W0SELECT a, b W0FROM tbl` →
W0FROM kalıyor). LLM SQL'i tek satır üretirse FROM boşlukla ayrılır → kaçar.
İnvestigator'ın "`\b` fail" teorisi YANLIŞ (regex satır-başını doğru yakalıyor).
**Fix:** anchor'ı `(?<![^\n])` → `(?:^|(?<=\s))` yap (satır başı VEYA boşluk sonrası).
String-literal FP'si yok (`'fooSELECT'` quote-öncesi). Tradeoff: teorik bareword FP
(` myWITH`) — pratikte yok-denecek, clause keyword'leri zaten glued olamaz.
**EK:** Çalışan backend v3.37.9 koduyla restart edilmemiş olabilir (telemetri log'u yok) →
restart hatırlat. Regex testi yeni `tests/` senaryosuna eklenecek (inline + line-start).

### B4-3 — Silinen kayıtlı rapor ekrandan hemen kaybolmuyor
**Kök neden (KANIT):** Delete akışı doğru wired — `report_detail_modal.js:822` DELETE
→ `close()` → `onDeleted()` → `home.html:1036` → `SavedReportsGrid.refresh()` →
`_fetchList()` taze GET. "Sayfa yenileyince gidiyor" = server-side silme ÇALIŞIYOR.
Ekranda kalması = refresh/render race veya read-after-write timing (refresh GET'i
DELETE commit görünür olmadan koşabiliyor) — runtime'a bağlı, kesin tek satır yok.
**Fix (robust, neden-bağımsız):** OPTIMISTIC removal — grid'e `removeItem(id)` ekle;
`onDeleted(deletedId)` önce kartı `_lastItems`'tan çıkarıp re-render etsin, SONRA refresh
ile reconcile. Anında kaybolma garanti. (`report_detail_modal.js` onDeleted'a `deletedId`
zaten geçiyor — home.html callback'i kullanmıyor; kullanacak şekilde düzelt.)

### B4-4 — Kayıtlı raporu çalıştır → "Veri kaynağı bilgisi bozuk veya eksik"
**Kök neden (KANIT — DB sorgulandı):** Tek kayıtlı rapor id=13: `source_id` kolonu **NULL**,
`wizard_state.source_id = 3`, `last_dialect` NULL. Kaynak 3 (Oracle localhost:1521 FREEPDB1)
**geçerli — bozuk değil**. Mesaj backend `db_smart_api.py:965 _data_corruption_500`'den.
Asıl sorun: `post_save_report_flat` (`db_smart_api.py:1276`) `source_id=body.source_id` —
FE göndermezse NULL; `last_dialect=None` her zaman. Yani **SAVE source_id'yi kolona
yazmıyor** (wizard_state'e düşmüyor). source_id çözülemeyen raporlar rerun'da hata verir.
**Fix:**
1. `post_save_report_flat` + session save (1205): `source_id = body.source_id or
   wizard_state.get('source_id')`; `last_dialect` source db_type'tan resolve (veya
   wizard_state.dialect).
2. (Veri onarımı) mevcut NULL source_id'li raporlar için: wizard_state.source_id'den
   backfill — küçük idempotent UPDATE (migration değil, opsiyonel one-shot) VEYA save
   fix'i yeterli (eski rapor rerun'da FE/BE wizard_state fallback'i zaten var: 1078-1088).
3. Hata mesajını ayır: source bulunamadı/eksik (404/eksik) vs gerçek corruption (canary
   host/port) — kullanıcı "bozuk" görmesin eksikse.

### B4-5 — "Yeni Keşif" fresh değil + çevrilmemiş i18n key
**Kök neden A (KANIT):** `db_smart_wizard.js:168` `_t('wizard.toast.select_table_first')`
ama i18n'de yalnız `wizard.hint.select_table_first` var (`aki_kesif_tr.json:39` +
`_en.json:39`) → ham key görünüyor.
**Fix A:** `wizard.toast.select_table_first` key'ini TR/EN'e ekle (veya kodu `.hint`'e
yönlendir). Tüm `wizard.toast.*` eksiklerini de tara.
**Kök neden B (KANIT):** `onNewReport → _akiKesifOpenWizard(null) → openAsModal({reportId:
undefined})`. `_resetWizardState()` (2585) var ve `if (!opts.reportId)` ile çağrılıyor
(~2765) AMA rapor detayını açıp inceledikten sonra `_state` (selectedTables/
selectedTableId/initialSelection) tam temizlenmiyor → yeni keşifte sızıyor.
**Fix B:** `_resetWizardState()`'in selectedTables + selectedTableId + initialSelection +
ilgili tüm alanları sıfırladığından emin ol; "Yeni Keşif"te (reportId yok) kesin çağrılsın;
gerekirse `closeModal`'da da reset.
